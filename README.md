# დარჩი · Hotel Reservation

„დარჩი“ არის სასტუმროებისა და ნომრების მოძიების დაჯავშნის ვებაპლიკაცია. სტუმარი ირჩევს ნომერსა და თარიღებს, აგზავნის ჯავშნის მოთხოვნას და პასუხს საკუთარ პროფილში ნახულობს. სასტუმროს მფლობელი იმავე საიტიდან მართავს სასტუმროებს, ნომრებს, ფოტოებსა და შემოსულ მოთხოვნებს.

## ტექნოლოგიები

- **ბექენდი** — Python, Django, Django REST Framework და PostgreSQL.
- **ფრონტენდი** — React, TypeScript, Vite, React Router და Tailwind CSS.
- **ავთენტიფიკაცია** — Django-ს სესიები, ქუქიები და CSRF დაცვა. ფრონტენდი API-ს `fetch`-ით უკავშირდება.
- **ადმინისტრირება** — Django Admin.

## ფუნქციები

- მთავარი გვერდი ჰერო სექციით, შერჩეული ქალაქებით, გამორჩეული ნომრებითა და დაჯავშნის მოკლე გზამკვლევით.
- სასტუმროების ჩამონათვალი ქალაქის ფილტრით. სასტუმროს დეტალებზე ჩანს ფოტოები და ამ სასტუმროს ნომრების ბმული.
- ნომრების ძებნა სასტუმროს, ტიპის, სტუმრების რაოდენობის, ღამის ფასის, თარიღებისა და გამორჩეული სტატუსის მიხედვით. შედეგები შეიძლება დალაგდეს ღამის ფასის ზრდადობით ან კლებადობით. ნომრების ფილტრები URL-ში ინახება.
- ნომრის დეტალები ფოტოგალერეით, თავისუფალი ღამეების კალენდრით და შესვლისა და გასვლის თარიღების არჩევით. დაჯავშნის ფორმაში ჩანს ღამის ფასი, ღამეების რაოდენობა და სავარაუდო ჯამი.
- რეგისტრაცია სახელით, გვარით, მომხმარებლის სახელით, ელფოსტითა და ტელეფონით. სისტემაში შესვლა მომხმარებლის სახელითა და პაროლით ხდება.
- პროფილში პირადი მონაცემების ნახვა, საკუთარი ჯავშნების ქალაქით გაფილტვრა და გაუქმება.
- პროფილიდან სასტუმროსა და ნომრის დამატება და რედაქტირება, ნომრის აქტიურობისა და გამორჩეული სტატუსის შეცვლა. სასტუმროსა და ნომრის გალერეებში დამატებითი ფოტოების ატვირთვა, აღწერისა და რიგითობის შეცვლა და გალერეიდან ამოღება.
- გვერდითი ფილტრები სასტუმროების, ნომრებისა და საკუთარი ჯავშნების გვერდებზე. ვიწრო ეკრანზე ფილტრების პანელი ღილაკით იშლება.

ახალი სასტუმრო განხილვის მოლოდინშია. საჯარო სიაში ჩანს აქტიური, გამოქვეყნებული სასტუმრო და მისი აქტიური ნომრები. Django მფლობელობას თითოეული სასტუმროს მიხედვით ამოწმებს. მფლობელი საკუთარ სასტუმროში ნომერს ვერ დაჯავშნის. ადმინისტრაციული ანგარიშები მართვის პანელში შედიან.

## ჯავშნის წესები

- საიტიდან გაგზავნილი მოთხოვნა იწყება `pending` სტატუსით. მფლობელის პასუხის მიხედვით ხდება `confirmed` ან `rejected`. გაუქმებული ჯავშანი `cancelled` სტატუსით რჩება ისტორიაში.
- კალენდარში ღამეებს მხოლოდ დადასტურებული ჯავშანი იკავებს. გასვლის დღე ჯავშნის ღამეებში არ შედის, ამიტომ იმავე დღეს სხვა სტუმარს შესვლა შეუძლია.
- შესვლის თარიღი მიმდინარე დღე ან მომავალი თარიღია. გასვლის თარიღი შესვლაზე გვიან უნდა იყოს. კალენდრის თარიღები ითვლება `Asia/Tbilisi` დროის სარტყლით.
- დადასტურებისას Django ტრანზაქციაში ბლოკავს ნომრის ჩანაწერს და მოწმდება, გადაფარავს თუ არა პერიოდი სხვა დადასტურებულ ჯავშანს.
- საბოლოო ფასს Django ითვლის ღამეების რაოდენობისა და მოთხოვნის შექმნის მომენტში მოქმედი ღამის ფასის მიხედვით. ნომრის ფასის შემდეგი ცვლილება არსებულ ჯავშანზე არ აისახება.

## მონაცემთა მოდელები

- `User` — საიტის მომხმარებელი.
- `City` → `Hotel` → `Room` — ქალაქი, სასტუმრო და კონკრეტული ნომერი. ერთ მფლობელს შეიძლება რამდენიმე სასტუმრო ჰქონდეს, ნომრის კოდი კი ერთი სასტუმროს ფარგლებში უნიკალურია.
- `HotelPhoto` და `RoomPhoto` — დამატებითი ფოტოები, აღწერითა და რიგითობით.
- `Booking` — მომხმარებლისა და ნომრის კავშირი თარიღებით, საკონტაქტო მონაცემებით, ფასებითა და სტატუსით.

ნომრის ტიპებია `single`, `double`, `twin`, `triple`, `family`, `deluxe` და `other`. პირველ ოთხ ტიპს შესაბამისი ფიქსირებული ტევადობა აქვს. `family` და `deluxe` ტიპებს საწყისი მნიშვნელობა აქვს, რომელიც ფორმაში იცვლება. `other` ტიპისთვის ტევადობა ხელით ივსება.

## ლოკალურად გაშვება

საჭიროა Python, Node.js და PostgreSQL. პროექტი აწყობილია Python 3.14-ისა და Node.js 24-ის გარემოში. ბრძანებები გაუშვი PowerShell-ში, რეპოზიტორიის ძირითადი საქაღალდიდან.

### 1. PostgreSQL და გარემოს ცვლადები

PostgreSQL-ში შექმენი ცარიელი ბაზა და აპლიკაციის მომხმარებელი, რომელსაც ამ ბაზაში ცხრილების შექმნის უფლება აქვს. რეპოზიტორიის ძირში, `backend` და `frontend` საქაღალდეების გვერდით, შექმენი `.env` ფაილი:

```dotenv
DB_NAME=hotel_reservation
DB_USER=hotel_user
DB_PASSWORD=your_local_password
DB_HOST=127.0.0.1
DB_PORT=5432
```

შეცვალე მნიშვნელობები შენი PostgreSQL-ის მონაცემებით.

### 2. Django

```powershell
python -m venv .venv
.\.venv\Scripts\Activate.ps1
python -m pip install -r backend/requirements.txt
python backend/manage.py migrate
python backend/manage.py createsuperuser
python backend/manage.py runserver
```

ადმინისტრირების პანელი გაიხსნება [127.0.0.1:8000/admin/](http://127.0.0.1:8000/admin/).

### 3. React

ცალკე ტერმინალში, რეპოზიტორიის ძირითადი საქაღალდიდან:

```powershell
Set-Location frontend
npm.cmd ci
npm.cmd run dev
```

საიტი გაიხსნება [localhost:5173](http://localhost:5173/). Vite განვითარების რეჟიმში `/api/` და `/media/` მოთხოვნებს Django-ს სერვერზე გადაამისამართებს.

ახალი ბაზით დაწყებისას ქალაქები დაამატე Django Admin-ში. შემდეგ შექმენი სასტუმროები და ნომრები ან გააგზავნე სასტუმროს განაცხადი ჩვეულებრივი მომხმარებლის ანგარიშიდან და დაამტკიცე Admin-ში. მონაცემთა ბაზის შიგთავსი და მომხმარებლის ატვირთული ფაილები რეპოზიტორიას არ მოჰყვება.

## API

| მეთოდი | მისამართი | დანიშნულება |
| --- | --- | --- |
| GET | `/api/auth/csrf/`, `/api/auth/me/` | CSRF ტოკენი და ანგარიშის მონაცემები |
| POST | `/api/auth/register/`, `/api/auth/login/`, `/api/auth/logout/` | რეგისტრაცია, შესვლა და გამოსვლა |
| GET | `/api/cities/`, `/api/hotels/`, `/api/hotels/{id}/` | ქალაქები და სასტუმროები |
| GET | `/api/rooms/`, `/api/rooms/{id}/`, `/api/rooms/{id}/availability/` | ნომრები, დეტალები და თავისუფალი ღამეები |
| GET, POST | `/api/bookings/` | საკუთარი ჯავშნების სია და ახალი მოთხოვნა |
| GET | `/api/bookings/incoming/` | მფლობელის შემოსული მოთხოვნები |
| POST | `/api/bookings/{id}/confirm/`, `/api/bookings/{id}/reject/`, `/api/bookings/{id}/cancel/` | დადასტურება, უარყოფა და გაუქმება |
| GET, POST | `/api/my/hotels/`, `/api/my/hotels/{hotel_id}/rooms/` | საკუთარი სასტუმროებისა და ნომრების სია და დამატება |
| PATCH | `/api/my/hotels/{id}/`, `/api/my/hotels/{hotel_id}/rooms/{room_id}/` | სასტუმროსა და ნომრის რედაქტირება |

| GET, POST | `/api/my/hotels/{hotel_id}/photos/`, `/api/my/hotels/{hotel_id}/rooms/{room_id}/photos/` | ფოტოების სია და ატვირთვა |
| GET, PATCH, DELETE | გალერეის მისამართი დამატებული `{photo_id}/` დაბოლოებით | ფოტოს მონაცემები, აღწერისა და რიგითობის შეცვლა, გალერეიდან ამოღება
