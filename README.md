# Hotel Reservation

სასტუმროს დაჯავშნის ვებაპლიკაცია.

პროექტი მომხმარებელს მისცემს სასტუმროებისა და ნომრების
დათვალიერების, გაფილტვრისა და დაჯავშნის შესაძლებლობას.

## ტექნოლოგიები

- ბექენდი: Python, Django, Django REST Framework
- ფრონტენდი: React, Vite, React Router
- მონაცემთა ბაზა: PostgreSQL
- ადმინისტრირება: Django Admin
- ავტენტიფიკაცია: Django-ს სესიები, cookie და CSRF დაცვა
- API მოთხოვნები: fetch
- დიზაინი: CSS ან CSS Modules
- ვერსიების კონტროლი: Git


## დაგეგმილი ფუნქციები

- მთავარი გვერდი გამორჩეული ნომრებით;
- სასტუმროების სია და ქალაქით გაფილტვრა;
- ნომრების სია და რამდენიმე ფილტრის ერთობლივი გამოყენება;
- კონკრეტული სასტუმროს ნომრების ნახვა;
- ნომრის დეტალების ნახვა და დაჯავშნა;
- რეგისტრაცია, შესვლა და გამოსვლა;
- საკუთარი ჯავშნების ნახვა, ქალაქით გაფილტვრა და გაუქმება;
- მონაცემების მართვა Django Admin-იდან.

გამორჩეული ნომრები არის ადმინისტრატორის მიერ
მთავარ გვერდზე გამოსაჩენად მონიშნული ნომრები — is_featured.

## მომხმარებლები და წვდომა

### სტუმარი

- ათვალიერებს სასტუმროებსა და ნომრებს;
- იყენებს ფილტრებს;
- რეგისტრირდება ან შედის სისტემაში.

### ავტორიზებული მომხმარებელი

- ჯავშნის ხელმისაწვდომ ნომერს;
- ხედავს მხოლოდ საკუთარ ჯავშნებს;
- აუქმებს საკუთარ ჯავშნებს.

### ადმინისტრატორი

- მართავს ქალაქებს, სასტუმროებსა და ნომრებს;
- ხედავს და მართავს ყველა ჯავშანს;
- მართავს მომხმარებლებს შესაბამისი უფლებებით.

დავალების ფორმულირება „ყველა დაჯავშნილი ნომერი“
პროექტში ნიშნავს: მომხმარებელი ხედავს საკუთარ ჯავშნებს,
ადმინისტრატორი კი — ყველა ჯავშანს.

ჯავშნის მფლობელს სერვერი განსაზღვრავს
მიმდინარე ავტორიზებული მომხმარებლის მიხედვით.

## რეგისტრაცია

რეგისტრაციის ფორმის ველები:

- სახელი;
- გვარი;
- username;
- ელფოსტა;
- ტელეფონი;
- პაროლი;
- პაროლის გამეორება.

username და ელფოსტა უნიკალური იქნება.
შესვლა განხორციელდება username-ითა და პაროლით.

## მონაცემთა მოდელები

დაგეგმილი მოდელებია:

- User — მომხმარებელი;
- City — ქალაქი;
- Hotel — სასტუმრო;
- Room — კონკრეტული ფიზიკური ნომერი;
- Booking — ჯავშანი.

კავშირები:

- ერთ ქალაქს აქვს მრავალი სასტუმრო;
- ერთ სასტუმროს აქვს მრავალი ნომერი;
- ერთ ნომერს სხვადასხვა პერიოდში აქვს მრავალი ჯავშანი;
- ერთ მომხმარებელს აქვს მრავალი ჯავშანი.

ნომრის ტიპები: single, double და deluxe.

ერთ სასტუმროში ნომრის შიდა ნომერი უნიკალური იქნება.

## დაჯავშნის წესები

- დაჯავშნა შეუძლია მხოლოდ ავტორიზებულ მომხმარებელს;
- შესვლის თარიღი არ უნდა იყოს წარსულში;
- გასვლის თარიღი უნდა იყოს შესვლის თარიღზე გვიან;
- ხელმისაწვდომობის ძებნისას ორივე თარიღი ერთად მიეთითება;
- თარიღების ფორმატია YYYY-MM-DD;
- პროექტის დროის სარტყელია Asia/Tbilisi;
- ერთ ნომერზე აქტიური ჯავშნების პერიოდები არ უნდა იკვეთებოდეს;
- ერთი სტუმრის გასვლა და მეორის შესვლა იმავე დღეს დაშვებულია;
- ღამეების რაოდენობასა და საბოლოო ფასს ბექენდი ითვლის;
- თანხები ინახება DecimalField-ში;
- ჯავშანი ინახავს დაჯავშნის მომენტში მოქმედ ღამის ფასს;
- ნომრის ფასის ცვლილება ძველი ჯავშნის ფასს არ ცვლის;
- გაუქმებული ჯავშანი ისტორიაში რჩება და ნომერს აღარ ბლოკავს.

ერთდროული დაჯავშნისგან დაცვა განხორციელდება PostgreSQL-ის
ტრანზაქციითა და Room ჩანაწერის select_for_update() ბლოკირებით.
ეს წესი გავრცელდება Admin-იდან შექმნილ ჯავშნებზეც.

## ფილტრები

სასტუმროები და ჯავშნები გაიფილტრება ქალაქით.

ნომრების ფილტრები:

- სასტუმრო;
- ნომრის ტიპი;
- მინიმალური და მაქსიმალური ღამის ფასი;
- შესვლისა და გასვლის თარიღები;
- გამორჩეული ნომრის სტატუსი.

ნომრების ყველა შევსებული ფილტრი ერთად იმოქმედებს.
ფილტრების მდგომარეობა შეინახება URL-ის query პარამეტრებში.

სასტუმროდან გახსნილ ნომრების გვერდზე Reset გაასუფთავებს
დანარჩენ ფილტრებს და შეინარჩუნებს სასტუმროს არჩევანს.

## დაგეგმილი გვერდები

| /rooms | ნომრები და ფილტრები |

ასევე მობილურზე გამართული განლაგება.

## Django Admin

დაგეგმილია:

- გასაგები დასახელებები და დაჯგუფებული ფორმები;
- სიებში საჭირო სვეტები, ძებნა და ფილტრები;
- ფოტოების წინასწარი ხედი;
- სასტუმროს ფორმიდან ნომრების მართვა;
- გამოთვლილი ფასებისა და სისტემური თარიღების მხოლოდ წაკითხვა;
- ჯავშნის შექმნისას ხელმისაწვდომობის შემოწმება;
- გაუქმება ისტორიის შენარჩუნებით.

პირველ ვერსიაში არსებული ჯავშნის ნომრისა და თარიღების
Admin-იდან შეცვლა შეიზღუდება.
